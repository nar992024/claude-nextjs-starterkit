# Claude 명령어: Review UI

UI/UX 관점에서 프론트엔드 코드를 리뷰합니다. 코드는 수정하지 않고 결과만 보고합니다.

## 리뷰 대상

- 인자: $ARGUMENTS
- 인자가 없으면 `git diff HEAD`와 추적되지 않은 파일을 대상으로 합니다.
- 변경 사항도 없으면 범위를 지정해 달라고 요청하고 멈춥니다.

## 프로세스

1. `CLAUDE.md`에서 이 프로젝트의 UI 규칙을 확인합니다.
2. 대상 코드와, 동작을 이해하는 데 필요한 주변 컴포넌트를 읽습니다.
3. 아래 항목을 점검합니다. 대상과 관련 없는 항목은 건너뜁니다.
4. 서버를 띄워 볼 수 있으면 실제 화면을 확인하고, 확인하지 못했다면 코드만 검토했다고 밝힙니다.

## 점검 항목

- **반응형:** 모바일 폭(390px)에서의 가로 스크롤, 잘리는 내용, 배치 변화
- **터치 대상:** 버튼, 링크, 입력창 등의 높이 44px 이상
- **상태 표현:** 로딩, 빈 목록, 오류, 비활성, 처리 중, 성공 상태와 안내 문구
- **폼 경험:** 라벨, 오류 위치와 문구, 입력값 유지, 중복 제출 방지
- **접근성:** 시맨틱 태그, 제목 구조, 키보드 조작, 포커스 표시, `aria-*`, 아이콘 전용 버튼의 이름
- **테마:** 다크 모드 대비, 하드코딩된 색상, 디자인 토큰 사용
- **일관성:** 기존 컴포넌트 재사용, 간격, 글자 크기, 용어와 문구

## 출력 형식

심각한 순서로 정리합니다. 문제가 없으면 없다고 짧게 말합니다.

```text
[심각도: 높음/중간/낮음] 파일:줄
- 문제: 사용자가 겪는 상황
- 제안: 구체적인 개선 방법
```

마지막에 확인한 범위와 확인하지 못한 항목을 적습니다.
