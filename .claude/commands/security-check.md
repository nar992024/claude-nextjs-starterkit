# Claude 명령어: Security Check

코드의 보안 취약점을 점검합니다. 코드는 수정하지 않고 결과만 보고합니다.

## 점검 대상

- 인자: $ARGUMENTS
- 인자가 없으면 `git diff HEAD`와 추적되지 않은 파일을 대상으로 합니다.
- 변경 사항도 없으면 범위를 지정해 달라고 요청하고 멈춥니다.

## 프로세스

1. 외부 입력이 들어오는 지점(API, 서버 액션, 폼, 파일 업로드, 웹훅)과 저장, 실행되는 지점을 찾습니다.
2. 입력이 코드에서 어떻게 흐르는지 따라가며 아래 항목을 점검합니다.
3. `npm audit --omit=dev`로 프로덕션 의존성을 확인합니다. `npm audit fix --force`는 실행하지 않습니다.
4. 실제로 악용할 수 있는 경로가 확인된 것만 취약점으로 보고합니다. 추측은 "확인 필요"로 구분합니다.

## 점검 항목

- **입력 검증:** 서버 측 스키마 검증, 타입과 길이 제한
- **인젝션:** SQL, NoSQL, 명령어, 경로 조작, SSRF
- **인증과 세션:** 인증 누락, 비밀번호 저장 방식, 토큰 만료와 쿠키 속성
- **권한:** 소유자 확인, 다른 사용자 자원 접근(IDOR), 관리자 기능 보호
- **출력:** XSS, `dangerouslySetInnerHTML`, 오류 메시지와 응답의 내부 정보 노출
- **비밀 정보:** 코드와 로그의 키, 토큰, 클라이언트로 노출되는 환경 변수(`NEXT_PUBLIC_*`)
- **웹 보안:** CSRF, CORS, 보안 헤더, 요청 제한
- **의존성:** 알려진 취약점이 있는 패키지

## 출력 형식

심각한 순서로 정리합니다. 응답에 비밀 값 자체는 적지 않습니다.

```text
[심각도: 치명/높음/중간/낮음] 파일:줄
- 취약점: 종류와 내용
- 악용 경로: 공격자가 입력하는 값과 결과
- 해결: 구체적인 수정 방법
```

마지막에 확인 필요 항목과 점검하지 못한 범위를 적습니다.
