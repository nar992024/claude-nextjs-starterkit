# Claude 명령어: Optimize

성능 최적화 방안을 제안합니다. 코드는 수정하지 않고, 사용자가 선택한 항목만 이후에 적용합니다.

## 분석 대상

- 인자: $ARGUMENTS
- 인자가 없으면 주요 경로를 훑어보고, 범위가 넓으면 우선순위가 높은 곳부터 봅니다.

## 프로세스

1. `CLAUDE.md`와 프로젝트의 프레임워크 버전을 확인합니다. 버전별 동작은 설치된 문서로 확인합니다.
2. 측정할 수 있으면 먼저 측정합니다. 빌드 결과, 번들 크기, 응답 시간, 쿼리 수 등을 활용합니다.
3. 프론트엔드, 백엔드 중 프로젝트에 해당하는 항목을 점검합니다.
4. 측정 근거가 있는 문제와 코드만 보고 추정한 문제를 구분합니다.
5. 효과에 비해 복잡도만 늘리는 최적화는 제안하지 않습니다.

## 점검 항목

**프론트엔드**

- 불필요한 클라이언트 컴포넌트와 큰 의존성, 지연 로딩 가능한 코드
- 렌더링 방식과 캐싱(프리렌더링, 스트리밍, `use cache`)
- 이미지와 폰트 최적화, 레이아웃 이동(CLS)
- 불필요한 리렌더링, 스토어 셀렉터 범위

**백엔드**

- N+1 쿼리, 인덱스, 페이지네이션 없는 조회
- 캐시 적용 지점과 무효화 방식
- 직렬 처리 중인 독립 작업, 커넥션 관리
- 응답 크기와 불필요한 필드

## 출력 형식

기대 효과가 큰 순서로 정리합니다. 개선할 곳이 없으면 없다고 말합니다.

```text
[우선순위: 높음/중간/낮음] 파일:줄
- 현재: 문제와 근거 (측정값 또는 "코드 기반 추정")
- 제안: 구체적인 변경 방법
- 기대 효과 / 비용: 개선되는 지표와 작업량, 부작용
```

마지막에 측정 방법과 확인하지 못한 항목을 적습니다.
